# 开发指南（RMT）

本文面向参与 RMT（若梦兔）开发的贡献者，介绍源码入口、模块职责、新增指令流程及验证与发布方式。具体函数签名、资源分类和工作流参数以当前源码为准。

## 开始开发与提交 PR

1. 从最新的 `Dev` 分支创建功能或修复分支，修改前阅读项目根目录的 `AGENTS.md`。
2. 先查找现有实现，确认不会重复添加功能；调整相关逻辑时清理过时或重复实现。
3. 按改动范围完成源码运行、编译或功能验证，在 PR 中说明变更目的、影响范围和验证结果。
4. **PR 的目标分支（base）必须选择 `Dev`，不能提交到 `master`。** 创建 PR 后再次检查目标分支。

版本号以 `RMT.ahk` 中的 `RMT_VERSION` 为准。功能新增、优化和修复记录写入 `Web/更新日志.md` 对应版本章节，按版本倒序排列；条目简洁，避免展开实现细节。

## 开发环境与目录

- Windows：主程序使用 AutoHotkey v2，界面基于 AHK-XAML / WPF。
- AutoHotkey v2 与 Ahk2Exe：源码运行需要 v2 解释器；编译需要 Ahk2Exe 和对应架构的基础程序。构建脚本默认查找 `C:\Program Files\AutoHotkey`。
- .NET Framework 4.8 或更高版本：界面与相关组件的运行环境，启动时由预检逻辑检查。
- Node.js：重新生成离线帮助文档时使用。
- 插件 DLL、模型及驱动：按实际使用的功能准备，依赖和下载规则参见 `Main/SelfCheck.ahk` 与资源策略文件。使用 x64 或 x86 时应匹配对应的二进制组件，具体功能还受插件支持架构限制。

主要目录：

- `RMT.ahk`：主程序入口与版本号。
- `Main/`：数据模型、触发、调度、运行时及主窗口。
- `Main/Shared/`：主程序与 Worker 共用的配置、指令数据及运行时逻辑。
- `Main/Util/`：宏执行、配置读写、输入模拟、识别、网络等工具。
- `Gui/`：指令编辑器、配置窗口及其他业务界面。
- `Thread/`：Worker、更新程序及其他辅助进程入口。
- `Plugins/`：插件封装、二进制依赖及部分插件源码。
- `Lang/`：语言文本与国旗资源；简体中文文本内置于源码。
- `Images/`、`Audio/`：界面图片与提示音。
- `Setting/`：运行时用户配置，当前主要使用 TOML；旧格式由兼容逻辑迁移。
- `Log/`、`Cache/`：程序运行日志与缓存。
- `Scripts/`：正式维护的构建、打包、翻译检查脚本及资源策略。
- `.github/`：CI、发布工作流及其辅助脚本。
- `Web/`：Markdown 文档、帮助页生成器及生成的 `index.html`。
- `ReleaseX64/`、`ReleaseX86/`：发行版所需的架构资源。
- `Test/`：临时验证内容，已加入 `.gitignore`。

测试脚本、夹具、参考网页、界面原型、截图及测试输出统一放在 `Test/` 下，按用途使用 `Test/scripts/`、`Test/reference/`、`Test/output/` 等子目录。不要强制加入 Git，也不要混入正式源码、文档或打包资源。

## 启动与宏执行

### 主程序启动

`RMT.ahk`：程序启动入口（环境预检、配置加载、界面初始化与触发服务启动）。

主要启动顺序：

1. 检查启动目录和更新恢复状态，通过 `EnsureSingleInstance()` 处理已有实例及命令转发。
2. 注册命令行入口，执行 `RuntimePrecheck()`、字体检查和 XAML 宿主预热。
3. 调用 `InitFilePath()`、`LoadCurMacroSetting()`、`HandleOpenArg()`，准备路径、当前配置及启动参数。
4. 注册原生下拉框滚轮保护，再调用 `InitData()`、`InitUI()`、`SetEditData()`。
5. 调用 `PluginInit()` 初始化插件与 Worker 池；必须在当前配置加载后执行，Worker 会读取配置。
6. 启动定时调度器、网络触发和语音触发，再调用 `BindKey()` 注册热键。
7. 启动命令队列监听，等待主窗口就绪后执行启动命令及延迟检查。

`SelfCheckMissingFiles()` 不是当前入口中固定执行的第一步；文件检查与按需补齐应沿实际调用入口排查。

### 宏执行路径

```text
热键 / 热字串 / 定时 / 网络 / 语音等触发
    ↓
各触发模块与任务分发
    ├─ 主进程执行
    └─ WorkPool → Thread/Work.exe 执行
           ↓
RunMacroTrigger（触发初始化、循环与收尾）
    ↓
RunMacroBodyOnce（线性宏体）/ GraphMacroUtil（流程图）
    ↓
ExecuteMacroCmdOnce → MacroCommandActions → 各指令处理函数
```

界面中的“多线程”通过独立 Worker 进程实现并行执行。主程序与 Worker 通过共享内存、环形缓冲区及消息通知协作，不能把主进程中的全局对象当作跨进程共享状态。

## 核心模块

以下文件名相对于所属目录。简单模块用一行说明；涉及执行边界或多文件协作的模块另作补充。

### 加载入口与数据模型（`Main/`）

- `AssetUtil.ahk`：主程序与 Worker 的共享加载入口（引入执行工具、共享模块及 IPC 消息编号）。
- `GlobalUtil.ahk`：主程序模块引用与全局初始化（加载 GUI、触发服务及主进程对象）。
- `MainGlobalUtil.ahk`：主进程专属初始化与辅助逻辑。
- `DataClass.Ahk`：配置、宏表条目及各类指令的数据模型。
- `SelfCheck.ahk`：运行依赖检查与缺失资源补齐。

共享执行逻辑通过 `AssetUtil.ahk` 引入；主窗口、控件操作及仅主进程使用的初始化放在主程序加载链中。新增共享函数时，应检查 `Thread/Work.ahk` 的引用链，避免 Worker 引用主程序专属函数。

### 共享模块（`Main/Shared/`）

- `MainSettings.ahk`：通用设置读取、默认值与 `InitDataFilePaths()` 路径登记。
- `RuntimeStartup.ahk`：运行数据初始化及指令文件、数据类映射。
- `MacroTableStorage.ahk`：宏表、模块及条目的 TOML 读写。
- `MacroTableRuntime.ahk`：宏表运行状态与按键回收。
- `CommandData.ahk`：指令拆分、参数数据读写与显示标记。
- `VariableResolution.ahk`：变量解析与条件求值。
- `WindowBinding.ahk`：窗口绑定相关共享逻辑。
- `Hotkeys.ahk`：热键相关共享工具。
- `ThemeSettings.ahk`：主题配置相关逻辑。
- `OfficialLanguages.ahk`：官方语言与语言文件登记。

### 执行与工具（`Main/Util/`）

- `MacroUtil.ahk`：宏触发、宏体执行及单条指令分发。
- `GraphMacroUtil.ahk`：流程图宏执行。
- `MacroClipboardUtil.ahk`：宏复制、粘贴及导入导出。
- `SerialUtil.ahk`：指令序列号分配与登记。
- `ConfigUtil.ahk`、`TomlUtil.ahk`：配置访问与 TOML 读写封装。
- `JsonUtil.ahk`：JSON 解析与序列化。
- `InputUtil.ahk`：输入指令及相关输入处理。
- `TextOpsUtil.ahk`：文本处理指令执行。
- `SearchUtil.ahk`、`SearchAllUtil.ahk`：图像搜索与多结果搜索。
- `SearchImageAssetUtil.ahk`：搜索指令图片资源管理。
- `CompareUtil.ahk`、`ExpressUtil.ahk`：条件比较与表达式计算。
- `FileIOUtil.ahk`、`ExcelUtil.ahk`：文件与 Excel 读写。
- `HttpRequestUtil.ahk`、`BrowserUtil.ahk`：网络请求与浏览器自动化。
- `WindowControlUtil.ahk`、`ProcessManageUtil.ahk`：窗口控件自动化与进程管理。
- `AiDecisionUtil.ahk`、`YoloUtil.ahk`、`TranslateCommand.ahk`：AI 判断、YOLO 检测与翻译指令。
- `PresssKeyUtil.ahk`、`HumanMouse.ahk`：底层按键模拟与人类化鼠标移动。
- `SharedMemory.ahk`、`RingBuffer.ahk`：进程通信使用的共享内存与环形缓冲区。
- `ShmVariableMap.ahk`：主程序与 Worker 的共享变量映射。
- `PluginUtil.ahk`：插件初始化与加载。
- `LangUtil.ahk`：语言文本查找与切换。
- `LogUtil.ahk`、`ErrorHandler.ahk`：日志记录与全局错误处理。
- `RmtCmdUtil.ahk`：命令行、单实例与命令队列相关逻辑。
- `RmtUpdate.ahk`、`RmtDownloadManager.ahk`：程序更新与后台下载管理。
- `Gdip_All.ahk`：GDI+ 图像处理封装。
- `XamlText.ahk`：XAML 文本转义工具。

`MacroUtil.ahk` 的主要入口：

- `RunMacroTrigger()`：管理一次触发的初始化、循环、前后钩子与收尾。
- `RunMacroBodyOnce()`：执行一段线性宏体，条件分支和循环体也会使用。
- `ExecuteMacroCmdOnce()`：执行单条指令，线性宏和流程图节点共用。
- `MacroCommandActions()`：集中登记指令名称与处理函数，运行时和静态检查共用。

兼容逻辑分为两类：`FixCompatUtil.ahk` 负责旧配置目录、文件的迁移，仅主程序加载；`CompatDataUtil.ahk` 负责运行时数据的旧字段补齐，供主程序与 Worker 共用。涉及旧配置时同时检查对应版本的 `Compatv*.ahk`，不要在 Worker 中执行迁移写盘。

- `WorkPool.ahk`：Worker 进程池（进程创建、任务排队、分发与通信）。
- `BindUtil.ahk`：全局热键、热字串注册与触发路由。

- `GestureUtil.ahk`、`GestureTouchpad.ahk`：手势与触摸板相关逻辑。
- `VariableUtil.ahk`：宏变量登记与相关处理。
- `RecordUtil.ahk`：键盘与鼠标宏录制。
- `RecordJoyUtil.ahk`：手柄宏录制。
- `JoyMacro.ahk`：手柄输入与宏支持。
- `TriggerKeyData.ahk`：按下、松开、长按、双击等触发状态管理。
- `WindowHotkeyManager.ahk`：窗口热键管理器（为指定窗口绑定热键）。

- `UIUtil.ahk`：主程序 UI 控件引用、窗口就绪协调及界面辅助逻辑。

## 界面模块（`Gui/` 与 `Main/MainWindow/`）

- `Main/MainWindowXaml.ahk`：主窗口入口（构造、窗口生命周期与页签切换）。
- `Main/MainWindow/`：主窗口按侧栏、AI 会话、宏列表、设置与静态页面拆分的方法。
- `Gui/MacroEditGui.ahk`：线性宏编辑器入口。
- `Gui/MacroEditor/`：指令目录、树交互、编辑、撤销与调试方法。
- `Gui/MacroEditModel.ahk`：宏编辑器树模型。
- `Gui/ImageProcessGui.ahk`：图片编辑器与样本对齐入口。
- `Gui/ImageEditor/`：画布、选点、遮罩、擦除及样本对齐方法。
- `Gui/MacroGraph/`：流程图编辑器的数据、节点、连线、事件、布局与编辑功能。

主窗口、宏编辑器和图片编辑器通过类内 `#Include` 将拆分的方法编译进原类，不能把这些方法文件当成独立脚本运行。语法检查与运行应从 `RMT.ahk` 或相应 Worker 入口进入。

常见修改位置：

- AI 消息显示：`Main/MainWindow/AiMessageMarkup.ahk`。
- 宏列表模板：`Main/MainWindow/MacroListTemplates.ahk`。
- 指令入口与子编辑器登记：`Gui/MacroEditor/CommandCatalog.ahk`。
- 断点与单步调试：`Gui/MacroEditor/Debugger.ahk`。
- 图片样本对齐：`Gui/ImageEditor/SampleAlignmentQueue.ahk`（调度）、`SampleAlignmentWorkers.ahk`（通信）、`SampleAlignmentMatching.ahk`（匹配）。

指令编辑器通常以 `*Gui.ahk` 命名，例如 `KeyGui.ahk`（按键）、`RunGui.ahk`（运行）、`RunProGui.ahk`（运行 Pro）、`SearchGui.ahk`（搜索）、`HttpRequestGui.ahk`（网络请求）、`YoloGui.ahk`（YOLO 检测）。配置与工具窗口包括 `SettingMgrGui.ahk`（配置管理）、`TriggerKeyGui.ahk`（触发键设置）、`TimingGui.ahk`（定时设置）及 `VarListenGui.ahk`（变量监听）。完整编辑器列表以 `CommandCatalog.ahk` 及实际引用为准。

### XAML 表单约定

- 新增单行输入框使用 `Style="{StaticResource RmtSingleLineTextBox}"`，文字起点与普通下拉框对齐。
- 新增多行输入框使用 `Style="{StaticResource RmtMultiLineTextBox}"`，文字顶部留白比原指令编辑器多行输入框少 6 DIP；保留已有输入框布局。
- 使用 AHK 构建控件时，通过 `.Style("{StaticResource RmtSingleLineTextBox}")` 或 `.Style("{StaticResource RmtMultiLineTextBox}")` 引用。
- 新增或调整指令表单时，每列标签按 5 个中文字加 1 个全角冒号预留宽度，随字号变化；标签简写到 5 个字以内，输入控件紧接标签列，同列起点对齐。
- 悬停提示用于补充用法、取值或限制。
- 拼接 XAML 文本时可使用 `EscapeXamlXml()`；换行、属性值及标记扩展仍需按使用上下文处理。

通用样式配置与继承规则参见 `Gui/COMMON_UI_STYLES.md`。

## Worker 与插件

### Worker（`Thread/`）

- `Work.ahk`：Worker 入口，编译为 `Work.exe`，执行并行宏及部分辅助任务。
- `WorkUtil.ahk`：Worker 初始化、任务处理与通信工具。
- `WorkGlobalUtil.ahk`：Worker 全局状态与初始化。
- `Update.ahk`：独立更新程序入口，编译为 `Update.exe`。

普通宏 Worker 不创建业务对话框，交互请求交由主进程显示并回传结果。修改通信协议、共享结构或执行代码时，必须同步验证主程序与重新编译的 Worker，避免旧二进制与新源码混用。

### 插件（`Plugins/`，部分列举）

- `AHK-XAML/`：XAML / WPF 界面宿主与控件封装。
- `OpenCV/`：图像识别与匹配。
- `RapidOcr/`、`TesseractOcr/`：OCR 引擎及模型支持。
- `ViGEm/`：通过 ViGEmBus 模拟虚拟手柄。
- `VIIPER/`：虚拟输入设备插件。
- `AhiDriver/`：基于驱动的键鼠输入支持。
- `ScreenCapture/`：截图辅助程序。
- `IbInputSimulator.ahk`、`MouseControl.ahk`：输入模拟与鼠标控制封装。
- `CLR.ahk`、`RMT/`：.NET 调用与 C# 辅助组件。
- `YOLO/`：模型推理与检测支持。
- `Translate/`：本地翻译推理支持。
- `ShmVar/`：共享变量组件。
- `RMTMcps/`：MCP 相关集成。

插件的开发、构建及架构限制优先查看各自的 README。不要依据目录存在就认定依赖已经齐全；模型、运行库或驱动可能需要额外准备。

## 新增指令流程

以下以需要独立配置数据的“示例”指令为例。先选择结构相近的现有指令作为参考，并检查是否可复用已有能力。

1. **定义数据模型。** 在 `Main/DataClass.Ahk` 新增数据类，定义默认字段及 `SerialStr` 等必要属性。`SerialStr` 标识一条已保存的指令配置，不是指令类型本身；通过 `GetCMDSerialStr("示例")` 分配，避免手工拼接序号。
2. **登记存储与类型。** 在 `Main/Shared/MainSettings.ahk` 的 `InitDataFilePaths()` 中登记配置文件路径，再在 `Main/Shared/RuntimeStartup.ahk` 的 `InitData()` 中补充 `DataFileMap` 和 `DataClassMap`。指令类型、配置文件与数据类要对应，主程序与 Worker 共用这套映射。
3. **实现编辑器。** 在 `Gui/` 新增编辑器，通过 `GetMacroCMDData()` 与 `SaveMacroCMDData()` 读取、保存参数，遵循现有编辑器的新增、编辑、确认与取消接口。新增输入控件遵守上述 XAML 约定。
4. **登记编辑入口。** 在 `Gui/MacroEditGui.ahk` 引入编辑器；在 `Gui/MacroEditor/CommandCatalog.ahk` 中补齐指令名称、图标和 `SubGuiConfig` 等登记项。按实际需要检查树节点、流程图、复制导出和变量登记是否也需适配。
5. **实现执行逻辑。** 在 `Main/Util/MacroUtil.ahk` 的 `MacroCommandActions()` 中添加 `"示例", OnExample` 映射，实现对应处理函数。复杂逻辑可拆到独立工具文件，并通过共享加载入口引入，确保主程序与 Worker 都能调用。
6. **补齐兼容与文档。** 为旧数据缺失字段提供默认值；确需迁移文件时走主进程兼容入口。同步指令手册、翻译和当前版本更新日志。新增资源时登记打包分类及下载策略。
7. **验证完整链路。** 检查新增、保存、再次编辑、取消、执行及导入导出；涉及变量、循环、流程图或 Worker 时分别验证相应路径。含等待或耗时操作的指令还需检查暂停、终止和超时行为。

内联参数指令或复用现有数据类的指令不一定需要独立配置文件，应沿用同类实现；不要机械地为每个指令新增文件。

## 运行、构建与验证

### 源码运行与编译

使用 AutoHotkey v2 运行项目根目录的 `RMT.ahk`。默认建议使用 x64，使用其他架构时检查插件兼容性。

在项目根目录执行：

```powershell
# 编译 x64 主程序、Worker，并刷新更新程序
.\Scripts\Build.ps1

# 仅重编 Worker（同时刷新更新程序）
.\Scripts\Build.ps1 work

# 编译 x86 主程序与 Worker，并刷新更新程序
.\Scripts\Build.ps1 x86
```

主程序输出到根目录 `RMT.exe`，Worker 输出到 `Thread/Work.exe`。脚本可能结束本项目中占用输出文件的运行实例，编译前先保存编辑内容。不要把 `clean` 当作普通编译参数：它会清理指定数据，不带范围时清理 `Log/` 与 `Setting/`。

修改 `Work.ahk` 引用的指令执行逻辑、数据结构或通信代码后，需要重新编译 Worker。临时将多线程设为 0 可辅助排查主进程执行，但不能代替 Worker 验证。

若手工使用 Ahk2Exe，源文件选择 `Thread/Work.ahk`，Base 选择所需架构的 AutoHotkey v2 基础程序，图标使用 `Images/Soft/rabit.ico`。临时编译输出放在 `Test/output/`，确认成功后再替换正式 Worker。

### 翻译与帮助文档

```powershell
# 检查所有语言文件，不自动修复
.\Scripts\CheckTranslations.ps1

# 严格检查，发现问题时返回失败状态
.\Scripts\CheckTranslations.ps1 -Strict

# 根据 Markdown 重新生成离线帮助
node Web/JS/SingleHtml.js
```

语言登记在 `Main/Shared/OfficialLanguages.ahk`，当前包括简体中文、繁体中文、英语、西班牙语、法语、德语和意大利语。新增或修改界面文本时同步相应语言键；翻译检查脚本的 `-Fix` 会修改语言文件，使用后检查差异。

### 提交前验证

根据实际改动选择检查范围，并在 PR 中记录结果：

- 执行逻辑：覆盖正常输入、无效参数、变量替换及相关运行模式。
- GUI：检查打开、保存、取消、字号变化、主题及布局对齐。
- 配置：检查保存后重新加载；涉及旧数据时验证迁移与默认值。
- Worker：重编后验证任务执行、停止及主进程交互。
- 文档：重建帮助页并检查内容与导航。

当前 PR CI 执行 x64 主程序与 Worker、x64/x86 更新程序的编译及 AHK 编码检查；通过编译不代表已完成运行时功能验证。AHK 文件的编码、BOM 与 CRLF 规则以 `.github/scripts/check-encoding.ps1` 为准。

## 打包与资源发布

### 打包入口

`Scripts/PackRMT.ps1`：编译、翻译检查、帮助文档生成与发行包打包入口。

```powershell
.\Scripts\PackRMT.ps1
```

默认交互选择发行包类型；非交互参数、输出目录及 CI 选项参见脚本头部。`Scripts/Build.ps1` 用于开发编译，不生成完整发行包。

### 资源分类与校验

资源分类以 `Scripts/ResourceLayout.json` 为准，客户端下载策略以 `Scripts/AssetDownloadPolicy.json` 为准：

- 版本标签：语言、界面图标、主程序配套组件和界面引擎。
- `Common`：输入、音频、手柄、图像、OCR、语音、YOLO、翻译等共享插件及模型。
- `Patch`：VC++、DirectX、.NET、字体、系统补丁与离线运行环境。

每个版本与架构的 `A-Assets.json` 记录资源名称、分类、位置、大小、SHA-256 及压缩包内容。版本清单锁定该版本依赖；共享区更新不能改变旧版本所需的内容。Audio、Input、ViGEm 使用共用包，其他架构相关共享包按策略使用 `_x64.zip`、`_x86.zip`；共用包发布前应确认两种架构的内容一致。

客户端下载优先查当前版本附件，再按清单查找 `Common` 或 `Patch`。只有两站明确返回 404 时才按规则回退，网络错误和校验失败不能视为资源不存在。下载内容必须通过清单校验；兼容旧清单名的规则以下载器实现为准。

### 发布与维护边界

GitHub 与 GitCode 的资源发布由 `.github/scripts/resource_layout.py` 及 `.github/workflows/` 中的发布、补齐和共享资源维护工作流协同处理：

- 共享资源变化前，先归档仍被旧版本依赖的原文件并验证两站下载，成功后再替换共享文件。ZIP 内容比较以内部文件内容为准，避免仅因时间戳变化重复归档。
- 正式版本及未识别标签默认受保护，只允许增加资源，不能覆盖原文件、删除附件或删除重建标签；清单只能追加，不能修改已有依赖记录。明确的 F 测试版标签按工作流规则维护。
- 更新 `Common` / `Patch` 使用“更新共享或修补资源”工作流，提供新资源地址、目标附件名及 SHA-256，不直接覆盖共享附件。
- 自动发布、补齐、迁移与共享资源维护共用 `rmt-resource-publication` 并发组。发布中断后应沿用已锁定依赖，不得用旧构建回滚共享区。
- 新增资源必须先登记分类和架构策略，并检查所需的 x64/x86 下载包。共享文件缺失时，先确认有效快照或恢复原哈希文件，不能绕过校验继续发布。
- 标签重排、清单改名、资源清理及历史恢复属于专门维护操作，按当前工作流的参数与保护规则执行；不要将历史的一次性迁移步骤作为日常发布流程。

发布前检查工作流、版本号、资源清单及两站结果；具体维护选项以当前工作流定义为准。
