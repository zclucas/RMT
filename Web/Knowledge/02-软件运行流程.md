# 软件运行流程

源：`RMT.ahk`、`BindUtil.ahk`、`TriggerKeyData.ahk`、`MacroUtil.ahk`、`WorkPool.ahk`、`TimingUtil.ahk`

---

## 1. 启动顺序

`RMT.ahk` 启动后按固定顺序初始化：

1. `InitFilePath()` — 创建 `Setting/<当前方案>/` 及截图目录，绑定各 `*File.ini` 路径
2. `LoadCurMacroSetting()` — 读当前方案的 `MacroFile.ini` 到 `TableInfo`
3. `HandleOpenArg()` — 处理启动参数
4. `RegisterNativeComboWheelGuard()` — 防止滚轮误改未展开的原生下拉框
5. `InitData()` — 建立 `DataFileMap` / `DataClassMap`，加载指令缓存与变量
6. `InitUI()` — 主窗口
7. `SetEditData()` — 编辑器下拉、检测是否含手柄键
8. `PluginInit()` — OpenCV / OCR / ViGEm / AHI 等（最慢，放后面）
9. `MyTimingScheduler.Start()` — 定时宏：先跑「软件启动时」，再按堆排周期
10. `BindKey()` — 注册全局热键与宏触发键

主进程还会先 `LoadMainSetting()` 读 `Setting/MainSettings.ini`。

未点「应用并保存」的界面改动**不会**进入上述加载结果，因此看起来「配了但不触发」。

## 2. 热键绑定

`BindKey()` 做这些事：

- 软件级：休眠、暂停、终止全部、工具页快捷键
- `InitTriggerKeyMap()`：把各页签未禁用的宏触发键放进 `TriggerKeyMap`
- 菜单宏模块键 → 开/关轮盘
- 界面宏模块键 → 切换浮窗
- 页签热键、退出清理

触发键注册规则：

- 单键：`$*~键名`（不阻断原键，且忽略当前修饰键状态）
- 组合键：`A & B`；`UnorderedTriggerArr=0` 时还会注册 `B & A`
- 字串宏：`:` 开头，走 `Hotstring`
- 触发键以 `~` 开头表示穿透，且**不会**自动松开修饰键

休眠开启时：立刻终止全部宏、停定时调度、托盘图标换成暂停。取消休眠后定时恢复。

## 3. 一次按键如何变成一次宏

```
物理按键
  → AHK Hotkey
  → TriggerKeyData.OnTriggerKeyDown / OnTriggerKeyUp
  → 按前台窗口过滤出当前有效的宏列表（200ms 缓存）
  → 按 TriggerType 决定现在是否 Action
  → TriggerMacroHandler / OnToggleTriggerMacro
  → 单线程：本进程 RunMacroTrigger
    或多线程：WorkPool 把 TR 任务交给 Work.exe
  → 循环 LoopCount 次：
        开始提示音
        RunMacroBodyOnce（拆指令、逐条 ExecuteMacroCmdOnce）
        结束提示音
  → FinalizeMacroRun（开关复位、按需松开按住的键、改色块）
```

前台过滤：

- 模块或宏配置了前台，且当前鼠标窗口匹配 → 该条可触发
- 若没有任何「带前台且匹配」的项，则回退到**没填前台**的项
- 填了前台但窗口不匹配 → 这条不会进有效列表（常见「突然不触发」原因）

`仅前台运行宏`（设置项）是另一层：宏**已经在跑**时，若前台变了，会把该宏杀掉。没填前台的宏不受影响。

## 4. 宏执行循环

`RunMacroTrigger`：

- 清 `Killed` / `Pause`，循环计数归零
- `宏循环次数` 从 1 开始，`循环次数`（内层循环指令用）从 0
- `LoopCountArr == -1` → 无限循环，直到终止或 `循环-跳出`
- 鼠标键 + `LoopCount==1` + 在 `ContinueKeyMap` 里 → 按住可连续再跑（间隔 50ms，松手停）
- 每一轮：若暂停则等待；若已杀则退出；播开始音；执行整段宏；播结束音；处理跳过/跳出

`RunMacroBodyOnce`：

- `SplitMacro`：按 `,` `，` 换行 `⫶` 切开
- 逐条 `ExecuteMacroCmdOnce`
- 返回值非空时，把返回的指令**插入到下一条之前**（搜索未找到重试、宏操作「插入」都走这条）
- `分支-跳出` / `循环-跳过本轮` / `循环-跳出` 会中断当前层

`ExecuteMacroCmdOnce`：

1. 已被杀 → 返回
2. 暂停则等待
3. 指令以 `🚫` 开头 → 跳过（右键「跳过指令」）
4. 设置了「仅前台运行宏」且前台不匹配 → 杀宏
5. 去掉 `🚫⭐` 后按第一段去数字，得到指令名，查 `Actions` 表
6. 未知指令或执行异常 → 吞掉，当空结果（不会崩，但看起来像「这条没跑」）

## 5. 单线程 vs 多线程

| `MutiThreadNum` | 行为 |
|-----------------|------|
| `0` | 主进程里直接跑宏 |
| `-1` | 动态池：核心约 3 个 Worker，闲置约 30 秒回收，最多扩到 16 |
| `n`（1~10） | 固定 n 个 `Thread/Work.exe` |

多线程时：

- 主进程只负责热键、UI、派发 `TR`（触发）/`ST`（停止）
- Worker 独立进程执行指令，通过 `WM_MASTER_TO_WORKER` / `WM_WORKER_TO_MASTER` 通信
- 变量修改会 EVENT 广播回主进程再分发给所有 Worker
- 图形宏多分支：Worker 把分支列表交回 Master，Master 再派多个 TR
- 搜图等 DllCall 可能卡住 Worker，终止时往往直接杀进程再建（所以「智能终止」仍可能等 150ms 后强杀）

`MacroStopType`：

- 智能终止：先协作退出，150ms 不成再强杀
- 强制终止：立刻杀线程并新建，更快但更耗资源

## 6. 定时宏

`TimingScheduler`：

- `Start()`：若不是重载，先触发所有 `Type==2`（软件启动时）
- 其余按 `StartStamp` / 周期推进，用最小堆取下一次时间
- `Type==1` 单次：到点触发一次
- `Type==3`：按秒/分/时/天/周/月重复，直到 `EndStamp`
- 禁用、模块禁用、宏内容为空的项不会进调度
- 休眠会 `Stop()`，取消休眠再 `Start()`（启动时类型不会因取消休眠再跑一遍，除非重新启动软件）

## 7. 暂停 / 终止 / 结束

| 操作 | 效果 | 可恢复 |
|------|------|--------|
| 暂停（全局或单条） | `WaitIfPaused` 卡住，不继续下一条 | 是 |
| 终止单条 | `KilledArr=true`，循环退出 | 否 |
| 终止全部 | 清所有运行中宏 + Worker | 否 |
| 休眠 | 终止全部 + 解绑业务触发 | 取消休眠后热键恢复 |
| 重载 | 重新读盘，丢掉未保存改动（图形编辑器内存改动也可能保留，以界面说明为准） | — |

`FinalizeMacroRun`：

- 开关类型会把 `ToggleStateArr` 置回 false
- **仅「被终止」或「开关类型」会松开仍按住的键**
- 按下 / 松开 / 双击 / 长按**正常跑完**时，故意不松开宏里按下的键（所以宏末尾通常应自己补松开，否则会卡键）

## 8. 状态色块（给用户看的）

宏序号旁颜色：

- 无色：空闲
- 绿色：运行中（`ColorStateArr==1`）
- 终止色：被杀掉

用户说「按下没反应」：先问色块有没有变绿。

- 不变绿 → 触发阶段失败（禁用、前台、未保存、热键冲突、休眠）
- 变绿但没效果 → 执行阶段（按键类型、管理员、游戏反作弊、间隔太短、搜不到图）

---

## 9. 配置生效边界

```
改界面
  → 仅内存中的控件值
  → 点「应用并保存」才写入 ini 并重绑热键
  → 之后的触发才用新配置
```

迁入旧 `Setting` 文件夹会先备份到 `SettingOld`。覆盖安装/覆盖文件更新容易导致触发全失效，应走配置迁移或导入 `.rmt`。
